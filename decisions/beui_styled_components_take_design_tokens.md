# Styled components take design tokens; `Custom` only for values from content

Styled props take `Space`, `Padding`, `Size`, `Length`, `Stroke`, `Radius`, `ColorRole` and `TextColor` (`beui-components-styled/src/tokens.rs`), so a raw `8.0` doesn't compile. `Space` resolves through `Density` (comfortable moves each step from `Xs` up one step larger). `Space::Custom`, `Size::Custom`, `Stroke::Custom`, `Radius::Custom`, `ColorRole::Custom` and `TextColor::Custom` are escape hatches only for values from content: a user's tag colour, a remote cursor, a presentation background, a thumbnail or board cell, pan-zoom's zoom-scaled card radius and padding, and lengths other code computes with. Dimensions particular to one component (a calendar day cell, the palette's 560 width, the colour picker's area) stay private `Size::Custom` consts or `Extent::at_most` inside styled. Unstyled and base components keep taking pixels; styled resolves tokens before handing them down.

## Why

Before, outside beui about 740 `spacing=`, 180 `padding=` and many private pixel consts each picked their own values, and `Tree` had its own `Metrics` for density; resolving through `Density` makes compact and comfortable layouts come from the tokens. `ColorRole::Custom(theme.x.get())` existed only because some theme colours had no role, so the roles were completed rather than reading theme colours by hand. Tokens that styled itself doesn't use aren't real, so the scale doesn't grow for one component's dimension. `Radius::Custom` came back for pan-zoom because a fixed `Radius::Lg` on a card zoomed far out rounds it into a pill and zoomed in looks sharp beside its scaled outline. A source lint rejects `Extent::px` outside beui's crates, since a styled `Length` takes an `Extent` and `Extent::px` would write pixels into it.
