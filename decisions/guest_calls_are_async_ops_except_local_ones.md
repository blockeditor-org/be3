# Every guest call is an async op, except calls into a local interface

In the WIT worlds generated by be-wasm-ops-bindgen (the app protocol, the type-module protocol, the gpu and the network protocol), every function is an `async func`, a `stream<T>` or a resource's lifetime, carried as an op of the be-wasm-ops kernel. Only an interface named `local`, whose host runs on the guest's own thread or worker on every platform (the GPU device), may have plain `func`s, which return their result straight into the guest; the generator refuses a plain `func` anywhere else (guides/type_modules.md, Operations and WIT).

## Why

So native, the web and in process behave the same: only a host on the caller's own thread can answer synchronously, and on the web the host's state is not reachable from the guest's worker. A `local` call's flattened wasm arguments keep a per-draw call to a few wasm values with no encoding or copy, which the GPU needs.

The generated shapes follow wit-bindgen's, so moving to it later changes little.

## Rejected

- The component model: everything rides the pure-guest ABI instead, with WIT as the schema only.
